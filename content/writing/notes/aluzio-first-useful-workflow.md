This is a working outline for an Aluzio build note. It records questions to answer, not decisions already made or results already achieved.

## Start with one journey

A product description becomes easier to evaluate when it follows one person through one task. The useful unit is the whole journey: what starts it, what the product does, and how the person knows they have reached a useful result.

**To add:** A real example of the task Aluzio should help someone complete.

## Make the boundary explicit

For that example, describe:

- What the person provides at the start.
- Which steps the product is responsible for.
- Where a person needs to review or decide.
- What should happen when a step cannot be completed.
- What a useful result looks like.

These questions should help define a small scope without implying that every part needs to be automated.

## Leave room for evidence

A build note becomes more useful when it can connect a decision to something observed. The next version of this draft should include an example, the choice it informed, and what remains uncertain.
